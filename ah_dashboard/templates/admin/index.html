Log in with an AH login code

The easiest way to (re)connect the server's AH login: no tokens to copy by hand.

  1. Open AH's login page and log in with the AH account the server should use.
  2. At the end, the page tries to open an appie://login-exit?code=… link, which the browser can't open. Open the developer tools (F12): the Console or Network tab shows that link. Copy it.
  3. Paste it here straight away (a code works once, for a short time).

Set AH tokens

Replaces the current login. Tokens are stored encrypted on the server and are never shown again. The access token is optional: with only a refresh token, the server gets a new access token on first use. The refresh token looks like xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx; the access token starts with a number and "_". You can also paste AH's whole JSON answer into the refresh token field.

Dashboard users

Signing in is optional and goes through the login service: anyone with an account there can sign in, and the first sign-in creates the account here (at most {{ max_users }}). A signed-in user's settings (stores, filters, presets, likes, hidden products, language, theme) are saved on the server and synced to their other devices. No passwords are stored. Disabling or deleting a user signs them out everywhere; deleting also deletes their saved settings. An admin user has the same rights as the admin password, but only in a sign-in made with the authenticator code at the login service (REQUIRE_ADMIN_2FA). Removing admin, disabling or deleting them ends it at once. An account that is not linked to a login-service user yet (e.g. from the Google era) is linked on the first sign-in with the same username; Unlink lets the next sign-in with that username link again.
